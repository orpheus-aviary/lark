# M5 后续：多选 + 批量操作

> 2026-08-06。用户在 M5 验收后提出：曲库支持多选，下载输入框下面那一行（常驻的固定高度状态行）用来放批量固定 / 取消固定 / 删除 / 从列表移除。
> 上游：主计划 §5.4（右键菜单矩阵）+ R24（虚拟 all 只读）+ R7（reorder 锚点协议）；M5 子计划 M5-16（拖拽）。
> 前置已完成（同日提交）：状态色 token、四通道行状态、排序两轴、设置页宽度与缓存档位。
> 完成标准：`just check` + 全仓测试绿 + 用户手感验收。

## 0. 目标

1. 曲库表支持多选：复选框列 + Cmd/Shift 点选。
2. 选中 ≥1 行时，下载状态行变成批量操作条：**固定 · 取消固定 · 添加到歌单▸ · 从当前列表移除 · 删除**。
3. 右键菜单在选区内作用于整个选区。

**不做**：Cmd+A（用户否决，改用全选复选框）、Delete 键删除（误触代价太大）、多行整体拖拽、批量编辑歌名/歌手、批量导出。

## 1. 决策

| # | 决策 | 说明 |
|---|---|---|
| B-1 | **选择状态从 `selectedSongId: string \| null` 改成 `selectedIds: readonly string[]`**（有序，按点击先后）。`selectedSongId` 的现有三个消费者（行高亮、操作列常驻、EditLink 定位）改读 `selectedIds`；「定位」仍是单选语义（`selectOnly(id)`） | 有序是为了「添加到歌单」按用户点选顺序追加 |
| B-2 | **复选框列固定在最前**（用户定），宽 32px，表头是全选/全不选三态框（半选态用 `indeterminate`）。列宽计算把它当固定列（不参与 `share` 均分），和 `index` 一样从可分配宽度里先扣掉 | 表头框的语义 = 当前**视图内**全选（搜索/歌单筛过之后的那些） |
| B-3 | **点选规则**：单击行 = 只选它；**Cmd/Ctrl+单击** = 加减选；**Shift+单击** = 从锚点到该行的区间（按**当前显示顺序**算）；点复选框 = 只切这一行（等价 Cmd+单击）；Esc 清空。锚点 = 最后一次非 Shift 的点选 | 双击播放、右键、内联编辑都不受影响 |
| B-4 | **右键规则（Finder 同款）**：右键**选区内**的行 → 菜单作用于整个选区，标题显示「N 首歌曲」；右键**选区外**的行 → 先 `selectOnly(该行)` 再按单曲逻辑走。单选时菜单与今天完全一致 | 不做「批量」独立菜单，避免两套 |
| B-5 | **操作条占用下载状态行，选择优先**：有选区就显示操作条，没有就显示原来的下载状态/进度。下载进度仍可从右侧「下载任务」浮层看。该行高度**固定为 24px（`h-6`，用户定，已随前置批提交）**，有无选区都一样，按钮做成 `text-xs` 文字按钮（删除用 `text-destructive`），右端一个 ✕ 清空选择 | 该行 M4 就是常驻占位的，换内容零布局跳动 |
| B-6 | **固定/取消固定各出一个按钮**，不做 toggle：混合选区里 toggle 的含义没有唯一解。两个都幂等 | |
| B-7 | **请求策略**：添加到歌单 = **一次** `POST /playlists/:id/songs`（本就收列表）；固定 / 移除 / 删除 = **N 次**串行（并发会撞 claim），逐条统计；全成 → 一条成功 toast，有失败 → 「成功 X 首，失败 Y 首」并把第一条错误附上 | 几十首量级够用；真需要批量路由再单开 |
| B-8 | **删除必须确认**：ConfirmDialog 写清数量（「确定删除选中的 N 首吗？音频与歌词会一并移入废纸篓」）。移除/固定不确认（可逆） | |
| B-9 | **「从当前列表移除」的出现条件** = 单曲那条同源：`search === '' ∧ playlistId !== 'all'`（R24） | |
| B-10 | **拖拽与多选**：拖一行 = 只移动这一行，并**清空选择**（锚点协议一次一首；多行整体移动要拆 N 个请求，第一版不做）。请求在飞时禁二次拖的规则不变 | |
| B-11 | **刷新后选区自净**：`songs:changed` 重取列表后，选区里已不存在的 id 丢掉，其余保留；切歌单 / 改搜索 / 改排序 = 清空选择（视图变了，选区无意义） | 排序变化保留选区也行，但「Shift 区间」的锚点会错位，一律清空最省心 |
| B-12 | **批量操作期间禁止再次触发**：操作条进入 busy 态（按钮 disabled + 文案「处理中…」），完成后自动刷新列表 | |

## 2. 落点

- `stores/library.ts`：`selectedIds` + `selectOnly` / `toggleSelected` / `selectRange` / `selectAllVisible` / `clearSelection`；`refresh()` 落地时自净选区；`setPlaylistId` / `setSearch` 清空。
- `lib/selection.ts`（新，纯函数）：`toggleIn(ids, id)`、`rangeBetween(ordered, anchor, target)`、`pruneMissing(ids, songs)` —— 区间与自净的边界情况单测在这里，不进组件。
- `components/SongList.tsx`：复选框列进 `visible` / `CONTENT_WIDTHS`；行的 onClick 改为分发到选择规则；表头复选框。
- `components/SongRow.tsx`：新增复选框单元格；`isSelected` 改由 `selectedIds` 推导。
- `components/BatchActionBar.tsx`（新）：操作条本体 + 所有批量动作的执行与统计。
- `components/DownloadBar.tsx`：状态行改成「有选区 → 渲染 BatchActionBar，否则渲染现状态行」。
- `components/SongRow.tsx` 的 `SongContextMenu`：多选时的标题与动作转发。
