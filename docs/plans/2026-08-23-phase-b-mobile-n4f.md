## §1 开工前必须知道的

### 1.1 portable 那半已经全部写好了，本批基本是接线

| 要的东西 | 已经在哪 | 形状 |
|---|---|---|
| 认出收藏夹 / 合集 | `portable/download/link.ts:96-99`（`parseSongInput` 里） | `{ kind:'favorites', media_id, url }` / `{ kind:'collection', mid, season_id, url }` |
| 展开成条目 | `portable/download/preflight.ts:138` `fetchList` | `{ title, videos: {bvid,title,duration}[], error }` |
| 批量的 LLM 门 | `preflight.ts:113` `preflightBatch` | **零网络**；有 keyword 条目或 `clean` 条目而没模型 → 抛 |
| 成批入队 | `portable/download/engine.ts:313` `enqueueBatches` | 吃 `DownloadBatchGroupInput[]`，回 `DownloadBatchData[]` |
| 批次状态 | hub 已经带着（`downloads/hub.ts:35`，`onBatchesChanged` 从 N4b 就接上了） | `{ id, target, total, items[], created_at }` |

**手机上缺的只有三样**：展开的调用点、勾选的 UI、目标是「新建歌单」时的那条路。`downloads/preflight.ts:74` 的 `LIST_NOT_YET`（「收藏夹和合集要等下一批」）就是本批要拆掉的那句话。

### 1.2 🔴 N4e 刚踩过的坑，这一批的形状完全一样

`recognise` 对收藏夹/合集今天返回 `{ kind:'refused', message: LIST_NOT_YET }`——**和 N4e 之前的 keyword 分支一模一样**：一句写死的、说「等下一批」的话。N4e 的教训是「门开了之后没人接，而没有任何东西在看那条路」，代价是一次真机会话。**本批一开始就要有「展开成功」那条路的单测**，不是等设备告诉我。

### 1.3 部分成功是常态，而且它已经把截断折进 `error` 了

`fetchList` 从不为「拉到一半失败」抛错：拿到过东西就返回，`error` 说为什么停（`preflight.ts:178-186`）。**截断也走同一个字段**——`error === null && truncated` 时它自己填一句「列表过长，只取回了前 N 条（上限 200 页 / 5000 条）」。所以 UI 只需要**照实显示 `error`**，判据 32 的反测（去掉 `truncated → error`）也就落在 core 的单测里而不是设备上。

**只有一种情况会抛**：一条都没拿到（`videos.length === 0`）。那是「这个链接用不了」，不是部分成功。

### 1.4 「准入原子 / 执行逐项」是两件事，UI 必须让人分得出来

`enqueueBatches` 的原子性是**准入**的（`engine.ts:313-330`：校验目标 → 查重 → 容量 → 建歌单 → 注册）。**它不承诺所有下载都会成功**。落到屏幕上是两种完全不同的反馈：

- **准入失败** → 一句话，**当场**，在提交按钮下面（歌单没建、一条任务都没进队）。
- **执行失败** → 任务列表里那一条红字，批次进度照走（`total` 不变，失败的条目计进已完成）。

判据 33 要的就是这两者在 UI 上区分得出来。**不要用同一个提示区显示两者**——那正是 T5 记过的「两个数字渲染进一个字符串」。

### 1.5 5000 条上限落在手机上是什么样

`FETCH_LIST_ITEMS_MAX = 5000` / `DOWNLOAD_BATCH_ITEMS_MAX = 1000`（`shared/limits.ts`）。也就是说**一次展开最多 5000 行，而一次批量最多提交 1000 条**——两个数不一样，勾选超过 1000 就必须在提交前说清楚，不能等 `enqueueBatches` 抛。

渲染上：`FlatList` + **勾选状态不进每行**（一个 `Set<bvid>` 在页面顶层），否则 5000 个 `useState` 会把这屏卡死。N4d 已经记过「`FlatList` 只渲染可见行」——这次它是优点，但也意味着「全选」不能靠遍历已渲染的行。

### 1.6 收藏夹进不来分享面板，只能粘贴

N0b-4c 实测：bilibili 的收藏夹分享直接进它自己的发动态发布器，到不了系统 chooser。**所以本批的唯一入口是粘贴框**，分享 intent 那条路不用管（它送过来的永远是单个视频）。

### 1.7 展开是一次可能很慢的网络往返

200 页 × 每页一次请求，最坏几十秒。三件事因此要定：**要有「正在取列表」态**（N4d 的短链已经有这个形状）· **要能取消**（`AbortController`，随离开页面而 abort）· **展开不属于「下载」，不 `arm()` 前台服务**——它在前台、有人在看着屏幕，而 `arm()` 是为熄屏后的下载准备的。

### 2.2 状态机（N4 §2.5 的 favorites/collection 那一支，展开）

```
粘贴收藏夹/合集链接
      ↓  （离线 parse，零网络——识别到此为止，不碰网络）
  [列表已识别：「收藏夹」/「合集」]
      ↓  点「下载」（就是 N4d 那个按钮，不新增）
  全屏勾选页挂载 ──→ [正在取列表…]（可取消 = 关掉这一页）
                          ↓
          ┌───────────────┴───────────────┐
          ↓                               ↓
    一条都没拿到                    拿到 N 条（error 可能非空）
    → 关页 + 拒绝，说原点原话              ↓
                                  · 歌单名 = 列表标题，**点一下可改**
                                  · error 非空 → 顶部一行照实说
                                  · 全选 / 反选 / 计数（默认全选）
                                  · 命名模式（记忆，无模型时 clean 灰）
                                          ↓
                                  提交 = 一次 enqueueBatches
                                          ↓
                            准入失败 → 当场一句话（歌单没建、零入队）
                            准入成功 → 回添加页，任务列表顶部出现 M/N
```

**展开的时序完全照桌面**：桌面在**对话框挂载时**展开（`BatchSelectModal.tsx:130-170`），而对话框只在显式提交动作之后打开——识别阶段一个包都不发。手机的识别是**每次防抖都重跑**的（N4d 决策 g），所以「识别即展开」会变成每敲一下打一次 bilibili；把展开放在选择页挂载，两端就是同一条时序。

### 2.3 提交映射（照桌面，决策 i 原样继承）

```ts
// 一个列表组 = 一个 group = 一次 enqueueBatches
enqueueBatches([{
  target,                                  // BatchTargetInput
  items: chosen.map((v) => ({
    kind: 'video', bvid: v.bvid, page: null,
```

## §4 判据（31–33，**每条标归属**）

31. **【上机】** 粘一条**收藏夹**链接 → 点下载 → 选择页自动展开成条目列表 → 反选掉几条 → 歌单名默认是列表标题（**点一下改一次，验证它真的用了改后的名字**）→ 提交 → 批次进度 M/N 走到底，**歌单里按 bvid 比对是勾选的那些**（不按条数，见 §6）。**合集同走一遍**。顺带看展开 200+ 条时的掉帧。
32. **部分成功如实说**。**【单测】** `fetchList` 截断时 `error` 非空且点名上限（**反测**：去掉 `truncated → error` 那一步 → 必须红）· 薄壳把 `error` 原样递给 UI，不改写 · 一条都没拿到时是拒绝而不是空列表。**【上机】** 只看一眼：`error` 非空时那一行真的在屏幕上。
33. **准入与执行分开**。**【单测】** 准入失败（空歌单名 / 超 `DOWNLOAD_BATCH_ITEMS_MAX`）→ **没建歌单、没入队**，错误从 `enqueueBatches` 出来；执行失败不影响同批其它条目。**【上机】** 两种反馈落在**不同的位置**（准入 = 提交按钮下面那行；执行 = 任务列表里那条红字）。

**不验**：批次级取消 · 5000 条满载 · 合集的分页边界（`FETCH_LIST_PAGES_MAX`）——都记成「有代码、有上限常量、没跑过」。

**关闭口径由用户给定：能照 PC 端就照 PC 端。** 每一条都先去读了桌面实际怎么做的，下表的「桌面」列是代码而不是印象。三条对不上的单独处理：**b 是我 v1 写错了**（已按桌面改正）· **f 与 h 经用户确认**。
