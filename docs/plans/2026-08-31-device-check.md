## A · 分P 现在是一个「合集」（这一批的主改动）

**改了什么**：以前手机上分P 会提交到「存到」选的那个目标，不建歌单、标题只读；桌面则新建一个以视频标题命名的歌单。现在两端一样了。

| # | 步骤 | 应该看到 |
|---|---|---|
| **A1** | 添加 → 粘一个**多 P** 链接（不带 `?p=`）→ 回车 | 分P 页直接展开。**顶上多了一行「新建歌单」和一个可以点进去改的输入框，里面预填视频标题**。下面的分P 列表**一个都没勾**。 |
| **A2** | 什么都不改，勾 2 个分P → 下载 | 回到添加页，任务列表里出现 2 条。**歌单 tab 里多了一个歌单，名字 = 视频标题**，点进去 2 首。 |
| **A3** | 再来一次同一个链接，这次**把歌单名改成别的**（比如「测试合集」）→ 勾 1 个 → 下载 | 新歌单叫 **「测试合集」**，不是视频标题。 |
| **A4** | 看 A1 那一屏，**确认没有「存到 · 仅曲库」那一行了** | 那行已经删掉——组自己建歌单，「存到」对它没有意义。 |

🔴 **A1 的「零勾选」是有意的**：打开文件夹的人要整个文件夹，而这一屏存在就是为了让人挑。如果打开时是全勾，那是回归。

## B · 收藏夹 / 合集没有被带坏（回归）

| # | 步骤 | 应该看到 |
|---|---|---|
| **B1** | 添加 → 粘一个**收藏夹**链接 → 回车 | 和以前一模一样：走一遍列表、顶上「新建歌单」+ 可改的名字、**全部勾上**。提交后建出歌单。 |

（B 组只是确认 A 那一批没有顺手改坏它——两者现在共用同一个 wire shape。）

## C · 自动重试用的是原来那次的命名（这一批的第二处改动）

**改了什么**：以前手机的自动重试会用**此刻**设置页/添加页记着的命名模式重下，于是一首以「原标题」提交的歌，可能在它失败的那几分钟里因为有人拨了 chip 而以「清洗命名」落库。现在重放的是那个任务自己已经解析好的目标。

| # | 步骤 | 应该看到 |
|---|---|---|
| **C1** | 设置 → 确认「下载失败自动重试」是 **1 次**（默认） | 就是 1 次。 |
| **C2** | 添加页把「命名」拨到 **原标题** → 粘一个**单 P** 链接 → 下载 → **在它还在下的时候把手机调成飞行模式**，等它失败 | 下载记录里出现一条失败（`超时` 或 `连接失败` 那一类）。 |
| **C3** | 关掉飞行模式；**在重试发生之前**把「命名」拨到 **清洗命名** | —— |
| **C4** | 等自动重试跑完 | 🔴 **歌落库的名字是「原标题」那一版**（视频的完整标题），**不是**被模型清洗过的歌名/歌手。下载记录里这首歌**只有一行**，不是两行。 |

**如果 C2 那一步很难造出失败**：把手机连到一个断网的 WiFi 也行，或者干脆跳过 C——这条在电脑上有单测钉着（`enqueueRetry` 重放的 target 与原任务逐字段相同，含 naming），真机这条是「人能不能看见」的那一半。**跳过就说一声，我记进 backlog 而不是当它验过。**
