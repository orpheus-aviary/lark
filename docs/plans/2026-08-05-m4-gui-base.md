## 0. 目标

1. **Electron 壳成为正式宿主**：daemon spawn/确权、单实例、窗口管理、`lark-media://` 协议代理（spike §6.3 定稿逐条移植）、token 链路（preload `getDaemonToken()` + transport `getAuthHeaders`——M2 留下的两处欠账在此结清）。
2. **renderer 基座**：Tailwind v4 + shadcn/ui、zustand 按域 store + data-bus、SSE 订阅（gui 注册 / 409 恢复 / player 命令 ack）、platform adapter 隔离 preload。
3. **功能对齐 Go 版**：歌单下拉管理、歌曲列表（可选列/列宽/双击编辑/右键菜单）、搜索、排序、播放器（4 模式/进度条/快捷键）、歌词 3 行同步 + offset 微调、下载栏 + 批量弹窗 + 实时进度 + 取消、本地 mp3 导入、Toast、自动深浅主题、字号。
4. **验收自动化**：CDP 驱动在副本 nest 自跑（安全契约见 M4-14）；用户手动项只剩「出声」、观感与原生对话框。

## 2. 调查输入（2026-08-05，四路并行调查结论摘要）

- **gui 现状**：M0 骨架——main 无 spawn/单实例/协议，preload 只有 `daemonUrl`（`getDaemonToken` 注释占位未实现），renderer 的 `configureTransport` 没配 `getAuthHeaders`（现在打任何非 `/status` 端点都 401）。零 UI 依赖（无 Tailwind/shadcn/zustand）。CSP 插件已在 `electron.vite.config.ts` 落地（dev/prod 两态）。
- **daemon 契约已完备**：`/events`（query 白名单严格、心跳 15s 注释行、写背压 1MiB 断线）、gui 两步握手（register 铸 id → `?role=gui&gui_id=` attach；**容量 8 / 断线 TTL 10 分钟 / daemon 重启注册表清空**）、409 `GUI_REGISTRATION_REQUIRED` 恢复协议（`scripts/demo-gui-sim.mjs` 是全流程参照）、player 九命令 ack 四分支（200/502 `GUI_ERROR`/504 `GUI_TIMEOUT`/409 `GUI_OFFLINE`）、`GET /download/tasks` 快照（终态任务环 100 / 批次环 20，`final` 快照 + `failed_playlist_ids` 软失败通道）、CORS 放行 `Origin: null`（build 后 `loadFile`）。**`GET /status` 只带 pid/uptime/version，不携带数据目录身份**——复用判定必须另建契约（M4-2）。
- **owl 参照**：探测只信 `GET /status` 不读 pid 文件；spawn `process.execPath` + `ELECTRON_RUN_AS_NODE` + detached/unref，**绝不注入 token env**；确权 = `status.pid === child.pid`，退出只停 owned；单实例锁在模块顶层；`getDaemonToken` 必须是函数（contextBridge 冻结值）；renderer 无 Context Provider，zustand + data-bus 单调计数器；Tailwind v4 走 vite 插件、无 config 文件；shadcn 用 `radix-ui` 伞包。**owl 没有的、lark 要自建**：深浅主题（owl 纯深色）、通用 Toast、文件对话框、自定义协议。owl 也没有 respawn/supervisor。
- **Go 版基线**（细节见 §4 裁决表）：单列垂直布局（TopBar / InteractionBar / SongList / ProgressBar / Controls / LyricsDisplay / StatusBar / Toast）；排序是前端 `localeCompare('zh-CN')` 七态循环；列宽/排序/列显隐/播放模式均不持久化；删除无确认；进度显示只有阶段文字 + `n/total` 计数；断线重连 = 3 秒后整页 reload；搜索实际最多 50 条（后端参数名 bug）；右键菜单是**条件渲染六项**（添加到歌单仅当存在用户歌单、移除仅非 all，**无「播放」项**）。
- **缺口**（GUI 要用但 shared/daemon 没有）：player 命令/report/ack 等响应无命名类型、`PATCH /config` 与各写请求无 body 类型、`/lyrics` 是 text/plain 走不了 `request()` 的信封解析、无 `parseLarkEvent` / `download:status` 去重 helper、token 路径知识只在 `@lark/core`、daemon 无 bin 字段（spawn 需自行解析 `@lark/daemon/cli`）、report 频率 daemon 侧零约束（GUI 自定）。

`nest_dir` 匹配且 `local_api_version` 相等 → 复用**（**永不认领所有权**）；**200 但 `nest_dir` 失配 → 弹框中止**（「端口被另一数据目录的 daemon 占用」——恰好覆盖复制过 token 的情形；比对双方都过 `realpath` 归一）；**200 但 `local_api_version` 不等、或 404（M3 及更早的 version, local_api_version}`，**复用只比 `local_api_version`**（包版本长期 0.1.0，精确比对识别不了协议变化）；daemon 自身与 GUI 都从该子路径取值（单一来源）；**401 → 弹框中止**（token 对不上）；**其余任何非 200 / 无效 JSON / 网络错 → 无法确证身份，弹框中止**；`/status` 可达但本 ### 4.1 虚拟 all 与列表视图的条件矩阵

daemon 侧：all 的一切成员写操作 400 `VIRTUAL_PLAYLIST`；`POST /download/song` 的 `playlist_id` 只收 UUID。GUI 侧规则**在此冻结**：

| 场景 | 规则 |
|---|---|
| 当前视图 = 虚拟 all | 右键/行内**不显示「从当前列表移除」** |
| 当前视图 = 搜索结果（跨全库） | **同样不显示「从当前列表移除」**——结果行未必是当前歌单成员，且视图本身不是成员列表 |
| 当前视图 = 真实歌单成员列表 | 显示移除项，调 `DELETE /playlists/:id/songs/:songId` |
| 「添加到歌单 ▸」子菜单 | **只列用户歌单，排除虚拟 all**；无用户歌单时整项隐藏（Go 同款） |
| 单曲下载、当前歌单 = all | `POST /download/song` **省略 `playlist_id`**（只入库） |
| 单曲下载、当前歌单 = 真实歌单 | `playlist_id` 传该歌单 UUID |
| 批量目标「当前歌单」= all | `BatchTargetInput` 用 **`{kind:'all'}`**，**禁止传 `playlist_id:'all'`** |

### 4.2 批量弹窗 → 线协议映射（冻结）

| 弹窗概念 | 线协议 |
|---|---|
| 「单项下载」组的勾选项 | 逐条 `POST /download/song {input, playlist_id?}`：video 项 `input` = parse 返回的 `url`（保留 `?p=`），keyword 项 `input` = `query`；`playlist_id` 按 §4.1 |
| 收藏夹/合集组 | 一个 `DownloadBatchGroupInput`：`target` = `{kind:'new', name: 组标题}`（双击改名改的就是这个 name）；`items` = 勾选视频映射为 `{kind:'video', bvid, page: null, title}` |
| 「原标题」复选框 | 勾选 → item 的 `title` = fetch-list 返回的列表标题（信任路径）；未勾 → `title: null`（管线回落 LLM/视频自身标题） |
| fetch-list **partial success**（`error` 非空且 `videos` 非空） | 组头显示**警告条**（error 文案 + 已取到 n 条），列表保留可勾选；`videos` 为空才显示错误态。**不照 Go 版用错误区替换整组** |
| 勾选为零的列表组 | **过滤掉、不进请求**（daemon 要求 groups 与每组 items 均非空）；全部列表组勾选为零 → **完全跳过 `/download/batch`**，只执行单项 best-effort；单项组同样为空 → 确认按钮禁用（N=0） |
| **过滤后列表组**的 items 总数 > **1000** 或组数 > **20**（`POST /download/batch` 单请求双上限；**单项组不计入**——它走 `/download/song`，不占该端点限额） | **阻止提交**并提示分次（fetch-list 上限 5000 > batch 上限 1000 的差值、21 个收藏夹链接的组数溢出都不静默吞）；**不拆批**——拆批破坏「单请求原子」语义，M4 不引入 |
| 确认下载：两种提交语义分开表述 | 全部收藏夹/合集组合成**一个** `DownloadBatchRequest {groups}`——这部分是**单请求原子**（M3-5 全成败）；「单项下载」组在 batch 成功后**逐条顺序提交、best-effort**——途中失败（如 `QUEUE_FULL`，队列容量 1000 **含既有 pending**）即停止后续提交并 toast「已提交 n/m + 原因」。**对话框文案与结果反馈按两种语义分开写，不得暗示整次确认原子成功** |

### 4.3 player 命令执行裁决矩阵（renderer 侧，执行后 ack）

| 命令/情形 | 行为 | ack |
|---|---|---|
| `play`，歌在当前视图 | 播放 | ok:true |
| `play`，歌不在当前视图 | 回落到全库（all）查找并播放（Go 语义） | ok:true |
| `play`，歌无文件 | 不播 | **ok:false**，message `需要下载`（M5 接 ensure-file 后改） |
| `play-playlist` / `switch-playlist`，歌单不存在或加载失败 | daemon 不校验歌单存在——renderer **先 `GET /playlists/:id/songs` 加载成功、后提交切换**；加载 404/失败 → **保留原视图不动** | **ok:false** + message |
| `play-playlist`，未指定 song_id | 加载成功切视图 → 播第一首**有文件**的歌；空歌单/全无文件 → 只切不播 | 空/全无文件 → **ok:false** + message；否则 true |
| `play-playlist`，指定 song_id | 加载成功切视图 →（daemon 不校验成员归属）先在成员中找、找不到再全库找；找不到或无文件 → **视图保持已切换**、不播 | 找不到/无文件 → **ok:false** + message |
| `switch-playlist` | 同样先加载后切换，只切不播（Go 同款） | ok:true |
| `pause`/`resume`/`next`/`prev` | 执行；`resume` 无当前歌 → no-op | no-op → ok:true（幂等）；执行异常 → false |
| `seek`，position > duration | **clamp 到 [0, duration]** 后 seek | ok:true |
| `mode` | 设置模式（值已由 daemon 校验） | ok:true |
| **命令结算边界（两条规则，不许混）** | ① ack 只结算**同步执行 + `audio.play()` 的 Promise 结果**（reject → ack:false + 错误 message）；② **ack 发出后**才到达的 media error 无法追溯 ack——按播放器故障处理：停住播放器（M4-6）+ toast + 下一次 report 如实反映 | ① reject → **ok:false**；② 不改已发 ack |

### 4.4 外部变更对播放器与视图的影响（冻结）

删除/改动可能来自本端、CLI 或另一 GUI 会话，一律经 `songs:changed` / `playlists:changed` 刷新后对账：

| 变更 | 规则 |
|---|---|
| 当前播放歌曲已不在库 | **停播 + 清空 src/歌词/current_song，随后 report（current_song: null）**——已打开的文件流可能还在吐字节，但不许继续 report 幽灵歌曲 |
| 当前歌单已不存在（本端删除或他端触发） | **视图回落虚拟 all**（Go 删除当前歌单也是回 all）；播放遵循 D11（正在播的歌继续） |
| 当前播放歌曲仍在、元数据变了 | 同步刷新展示与 report 镜像里的 `name`/`artist`（不打断播放） |

## 7. 风险

| 风险 | 对策 |
|---|---|
| spike 裸 Electron 与 electron-vite 打包环境行为差异 | T6：正式 GUI × 真实 daemon（验收模式）完整六项，不抽测 |
| SSE 命令到达时无用户手势，autoplay 策略拦 `audio.play()` | Electron 默认 `no-user-gesture-required`，理论无碍；T4 验收显式覆盖「远程 play 出声」，被拦则 webPreferences 显式设 autoplayPolicy |
| pnpm 严格 store 下 react 双拷贝（owl 踩过，hook dispatcher 炸） | owl 的 vitest alias workaround 预防性移植（T2 测试基座） |
| ABI 翻转循环打断开发节奏（dev/gui-preview=148 / test=137） | recipes 双向自愈（M1 验收过）；文档写明混跑代价 |
| daemon 验收缝（限速/debug 路由）渗入正式路径 | 缝只在 `BootOptions` 且仅 testing 入口可开（M2 先例）；正式 CLI 无对应开关；「正常模式下 debug 路由 404」有守卫测试；capabilities 双向覆盖守卫在正常模式跑、不受影响 |
| shadcn 基件量大、批次膨胀 | 只引 M4 用到的基件（button/input/dialog/dropdown/context-menu/slider/popover/checkbox/tooltip 量级），不整包铺 |
| daemon 重启后媒体管线病态卡死（spike §6.3.8 已知限制） | daemonGeneration remount + `location.reload()` 末级兜底（仅确认换代后仍 error 时）；T6 验收含「重启 daemon 后免刷新继续 seek」 |
| GUI 侧写死 TTL 10 分钟 / 容量 8 与 daemon 硬编码漂移 | 409 恢复路径不依赖常数值（收到即重注册），常数仅注释说明 |
| pid 复用误杀（child 死后系统复用其 pid） | M4-2⑤：发信号前重新确认 `/status.pid === ownedPid`，失配即放弃 |

### 8.1 版本与来源定案

- UI 依赖全部按 M4-11 锁版一次装成，registry 上都在，**没有用到「安装失败即回报」那条退路**。
- shadcn 基件 10 个：`button` / `input` / `dialog` / `dropdown-menu` / `context-menu` / `popover`
  照抄 owl 已提交实现（改主题变量适配双态）；owl 没有的 `checkbox` / `slider` / `tooltip` /
  `sonner` 包装从 shadcn 上游 radix-ui 伞包时代源码手工引入。T3 另给 `context-menu` 补了
  上游的 `Sub` / `SubTrigger` / `SubContent`（「添加到歌单 ▸」要用）。
- 双态色板 = shadcn 上游默认 neutral（oklch）。owl 无动画库，组件里的 `animate-in` 类是无害死类，
  **没有**为此新增依赖。

### 8.2 实测修订与踩坑

- **`/status` 只回 pid/uptime/version**，所以复用判定另建了鉴权 `GET /api/instance`；
  daemon 的版本常量挪进无副作用的 `@lark/daemon/version` 子路径，否则 main 一 import 就把
  boot/server/core 整图拖进来，与「main 不加载 better-sqlite3」冲突（M4-1/M4-2）。
- **`ImportSongsRequest` 的字段名是错的**：shared 写 `paths`，daemon 从 M3 起读的是 `file_paths`。
  在 T5 第一个真实调用者出现时才暴露，已改 shared 对齐（`8885e35`）。
- **`contextBridge` 冻结 `window.larkAPI`**：CDP 里覆盖 `pickMp3` 会**静默失败**并弹出真实原生
  对话框——这正是 M4-14⑥ 预判的「原生对话框驱动不了」。导入流程测改为整体替换 `window.larkAPI`
  对象注入假 picker，真对话框留人工验收。
- **CDP 打字**：窗口不是系统焦点时，`Input.dispatchKeyEvent` 只发 `keyDown` 进不了 React 的
  `onKeyDown`，必须补 `char` + `text: '\r'`。
- **pino-roll 写的是 `lark.log.1`**（不是 daemon 打印的 `lark.log`），harness 读 Range 日志时要
  glob `lark.log*` —— 第一版按 `lark.log` 读，判据 2/3 假失败。
- **macOS `mkdtemp` 给 `/var/…`、daemon 报 `/private/var/…`**：GUI 的复用判定逐字比对两者，
  所以 `backupNest` 返回 realpath 后的路径。
- **`electron-vite preview` 不吃 `--remoteDebuggingPort`**（只有 `dev` 有），harness 改成直接用
  Electron 二进制跑 build 产物（`electron packages/gui --remote-debugging-port=…`），效果等价且能传参。
- **`backupDatabase` 的产物没有 WAL 边车**（M0 起写在注释里的说法是对的，T6 复核确认）；
  而**只读连接打开 WAL 库会自己造出 `-wal`/`-shm` 且关闭时不删**——断言「副本无边车」必须在
  打开副本之前做。
- **dev 态 console 里那条 404 是 Chromium 自动请求 `/favicon.ico`**（daemon 日志零 404），
  T7 打包配图标即消失；`accept-gui` 跑的是 build 产物，判据 5 不受影响。
- 媒体元素的 `has_file` 是**每次请求现探的磁盘状态**：列表拿到之后文件被删，GUI 仍会尝试播放并
  走 media error 停播路径（M4-6），刷新列表后才变灰显 + 拒播（§4.3）。实测确认两种表现都对。

### 8.4 验收后修正（`a9896ed`）与转入 M5 的一项

用户提了三条补充，两条属于「M4 交付的东西没做对」，当场修并实测：

- **列宽拖拽手感（D4 的实现偏离）**：Go 基线是「拖拽只改左列」，T3 实现却把未拖过的列做成
  「平分剩余宽度」，于是拖一列必然挤压邻居。改成访达式：每列宽度只由容器决定、彼此无关，
  分隔条只改左侧那一列，右侧整体平移，末尾操作列吸收差值，吸不下才整表变宽横向滚动。
  实测：拖 `name` +120px → `168→288`，右侧两列纹丝不动，尾列 `308→188` 吸收，表宽不变。
- **底部高度会跳**（用户要求确认，确实存在，且成因有两处）：歌词区用的是 `min-h-14`（最小值
  不是固定值），「未播放」是一行、播放是三行，且当前行字号跟 `--lark-lyrics-font-size` 走；
  下载状态行则是条件渲染，出现/消失时把交互栏撑高又收回。曲库列表是吸收剩余高度的 flex
  子元素，所以两处都会让整张表跳。改：歌词区固定 `h-20` + 当前行字号 `min(…, 1.75rem)` 封顶、
  状态行常驻 `h-5` 占位。实测：开始播放 `247px → 247px`、歌词字号调到 40px 仍 `247px`
  （列表高度同样不变）、状态行出现时交互栏 `64px → 64px`。
- **设置页转入 M5**（M4 本就把它列在「明确不做」里）：三条定案已写进 `PROCESS.md` 的 M5 条目
  ——主题进 config（`[theme] mode`，并冻结「外观进 config、视图态留 localStorage」）、设置页
  同时露 `window` 与 `log`、顺带做「记住窗口大小」。
