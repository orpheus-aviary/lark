# lark 0.4.1（桌面 + CLI）

一批小改动，主体是 Android 0.1.1 那一版在桌面这边的另一半：**一个新设置**，和**一个一直在说谎的错误提示**。

## 你会直接感觉到的

- **「自动下载下一首」（设置页，默认开）。** 顺序播到一首没有音频文件的歌，lark 会**去取回来再播**，而不是跳过它——0.4.0 的规则是「自然播完不许花流量」，代价是一个歌单会按「碰巧下过哪几首」的顺序播，而不是按它写的顺序播。想回到旧行为，把这个开关关掉即可（手动按下一首**一直**会去取，那是一次播放意图，不受这个开关影响）。
- **下载超时不再报「下载任务出现内部错误」。** 它以前掉进兜底错误码里，而超时恰恰是最常见的一类失败；现在它有自己的名字，说的是超时。

## 底下的

- 配置多了一节 `[playback]`（`auto_download_next`，配置文件里第一个布尔字段）。
- 本地协议 `LOCAL_API_VERSION` 7 → 8。**这一条是有代价的**：0.4.0 的 daemon 不认识 `[playback]`，而 0.4.1 的设置页要写它——所以两边必须同版本，见下。
- 删掉四个全仓无人引用的导出（对外行为无变化）。

## 兼容性

- **曲库不迁移**：schema 仍是 v3，0.4.0 的库直接打开。
- 🔴 **CLI 必须一起升到 0.4.1**：协议号变了，旧 CLI 会拒绝跟新 daemon 说话，反之亦然。`npm i -g @orpheus-aviary/lark-cli@0.4.1`。
- Android 端不受影响（它有自己的版本线，当前 0.1.1，且不经过 daemon）。

## 验收

发版前对**这一份代码和产物**跑了全部五套：`accept-gui` 15/15 · `accept-cli` 27/27 · `accept-m5` 22/22（真 bilibili）· `accept-sync` 36/36（真 skybridge server + 两台 daemon + 真 GUI）· `accept-pack` 28/28（对只读挂载的 dmg 本身）。单元测试 3410。
