# lark 0.4.0（桌面 + CLI）

从 0.3.0 起攒了三个多月的一批改动，主体是为 Android 端做的重构，桌面这边跟着变好、也跟着变了两处行为。

## 你会直接感觉到的

- **「需要下载」的歌不再是墙。** 以前点一首没有音频文件的歌是放不了的；现在点它 = 一次播放意图，lark 会去取回来再从头播。上一首 / 下一首也会去取，而**自然播完则跳过**——不会因为队列里有一首没下载就卡住。
- **同步断流会自己接上。** 加了两条：重新连上时补跑一轮（服务器不重放订阅之前的事件，所以断开期间别人的改动以前只能等下一次定时同步），以及一个 60 秒的空闲看门狗——半开的 socket 一个回调都不触发，靠它才发现得了。
- **一台设备可以有多个曲库**（为多账号准备）。没登录的那个是「本机曲库」，每个登录过的账号各有一个，互相看不见。切换只改一行记录，**重启才生效**——正在播放和正在下载的都不受影响。
- **`lark sync login` 现在会说清楚账号的曲库落在哪、要不要重启。** 以前它成功之后，下一条命令会告诉你「还没有登录」，而屏幕上唯一的建议是再登录一次。

## 底下的

- 整个业务图搬进 `@lark/core/portable`，与宿主解耦（这是 Android 端能存在的前提）。桌面走的是同一份代码。
- 本地协议 `LOCAL_API_VERSION` 6 → 7（多了 `GET /workspaces` 与 `POST /workspaces/switch`）。GUI、daemon、CLI 一起发，装同一版即可。
- 已撤销的设备在设备列表里收起来了——它们在服务器上删不掉（同步日志里每条变更都记着是哪台设备写的），而撤销后再登录会新注册一台，所以列表只会变长。

## 兼容性

- **曲库不迁移**：schema 仍是 v3，0.3.0 的库直接打开。
- **`~/orpheus-aviary-nest/lark/` 原地不动**——账号曲库是新目录，已有的那个不动。
- 建议 CLI 一起升到 0.4.0（协议号变了）。

## 验收

发版前对**这一份产物**跑了全部五套：`accept-gui` 15/15 · `accept-cli` 27/27 · `accept-m5` 22/22（真 bilibili）· `accept-sync` 36/36（真 skybridge server + 两台 daemon + 真 GUI）· `accept-pack` 28/28（对只读挂载的 dmg 本身）。单元测试 3317。
