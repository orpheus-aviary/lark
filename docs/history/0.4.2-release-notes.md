# lark 0.4.2（桌面 + CLI）

一个改动：**多选之后可以一键把缺的音频补下来**。

## 你会直接感觉到的

- **多选栏多了一颗「下载」**，就在「固定」左边，和其它批量动作一样常驻、没选东西时置灰。选中若干首点它，lark 只去取**带 `[需要下载]` 的那些**——已经在本机的一首都不碰。选中多行右键也有同一条（「下载 N 首」）。
- **它不是「重新下载」。** 「重新下载」是强制重取，选中 200 首就会把 180 首好好的文件也重下一遍；「下载」只补缺的那 20 首。单选一行时菜单里仍然只有「重新下载」——一首歌不存在「一半缺一半不缺」。
- **它会告诉你它干了什么**：「已开始下载 12 首；另有 3 首已在本机」，有失败就连第一条原因一起说（没有来源标识、又没配 LLM 的歌下不了，这一条由 daemon 回答）。

这一颗是给**新设备登录账号之后**准备的：同步只搬元数据，音频本体从来不过同步通道，所以刚登录完整个库都是 `[需要下载]`。以前只能一首首点开播放、或者用语义不对的「重新下载」。

## 要注意的

🔴 **如果你设了缓存上限**（设置 → 存储，默认是「不限」）：桌面的规则一直是**下新删旧**——每次下载完成都会按最近最少使用清理，直到回到上限以内。一次排几百首会把上限内的旧文件挤掉，**固定（pin）过的和导入的歌永远不动**。手机端那颗「全部下载」是另一套规则（撞到上限就停下并记成失败），两端在这一点上不一样，是各自的产品决定。

## 兼容性

- **曲库不迁移**：schema 仍是 v3。
- **协议没动**：`LOCAL_API_VERSION` 仍是 8，用的是 0.4.0 就有的 `POST /songs/:id/ensure-file`。所以 **0.4.1 的 CLI 和 0.4.2 的 daemon 能正常说话**，不升也可以；要升就 `npm i -g @orpheus-aviary/lark-cli@0.4.2`。
- Android 端不受影响（自己的版本线，当前 0.1.1）。
